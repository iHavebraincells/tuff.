02 / Event utility

Signal

A lightweight event object for connecting callbacks, firing events, and waiting for the next event. The API is defined in the environment bootstrap script.

Signal.new() Available

local signal = Signal.new()

Creates a new Signal instance with an empty connection list.

Signal:Connect(callback) Method

local connection = signal:Connect(callback)

Connects a callback to the signal. Returns a connection object containing its callback, parent signal, and connected state.

connection:Disconnect() Method

connection:Disconnect()

Marks the connection as disconnected and removes it from the signal's connection list.

Signal:Once(callback) Method

signal:Once(function(...))

Connects a callback that is automatically disconnected before its first invocation.

Signal:Fire(...) Method

signal:Fire(arg1, arg2, ...)

Invokes active callbacks asynchronously using task.spawn. The implementation clones the connection list before dispatching.

Signal:Wait() Method

local a, b = signal:Wait()

Yields the current coroutine until the signal fires, then resumes it with the fired arguments through task.spawn.

Example
local ready = Signal.new()

local connection = ready:Connect(function(message)
  print(message)
end)

ready:Fire("Ready")
connection:Disconnect()
03 / Networking

WebSocket

The bootstrap exposes a socket object backed by internal open, send, close, and poll functions.

WebSocket.connect(url) Available

local socket = WebSocket.connect("wss://example.com")

Opens a connection and returns a socket object. The same constructor is exposed as WebSocket.Connect, WebSocket.New, and WebSocket.new.

socket:Send(message) Method

socket:Send("hello")
socket:send("hello")

Sends a message through the socket. Strings are sent directly; non-string values are converted using tostring.

socket:Close() Method

socket:Close()
socket:close()

Closes the socket through the internal close handler.

socket.OnMessage Event

socket.OnMessage:Connect(function(message)
  print(message)
end)

Event-like object fired when the polling loop receives a message. It uses a BindableEvent when available, otherwise the Signal implementation.

socket.OnClose Event

socket.OnClose:Connect(function()
  print("Socket closed")
end)

Event-like object fired when the polling loop detects that the socket has closed.

Implementation detail: The bootstrap polling loop calls the internal poll function repeatedly and waits approximately 0.03 seconds between polls. The internal helper names are not part of the documented Lua API.
Example
local socket = WebSocket.connect("wss://example.com")

socket.OnMessage:Connect(function(message)
  print("Received:", message)
end)

socket:Send("Hello from Vynx")

06 / Runtime behavior

Registration and runtime notes

Initialization order

The initializer clears tracked closure and queue state, resets closure/signal/Oth state, tears down WebSocket state, captures the existing pcall reference, and then registers the libraries. It installs the instance hooks, creates _G and shared, and queues the Lua Signal and WebSocket bootstrap scripts for execution.

Aliases and table exports

Aliases are separate global names bound to the same native function implementation. Table exports are attached to a namespace table before it is placed in the global environment. The crypt, base64, and debug tables are made read-only after setup in the relevant registration code.

Hook restrictions

The hook implementation rejects access to a defined set of blocked service names and method names for executor-state calls. This includes purchase-related methods, selected account and capture operations, internal HTTP methods, and services such as ScriptContext and HttpRbxApiService. The block list is an implementation safeguard, not a complete security boundary description.

Reset behavior

ResetState() clears tracked executor closures, pending yield work, queued execution requests, and immediate drawing state. The initializer also resets library-specific state before registering the environment again.

07 / Runtime

Execution lifecycle

At a high level, the application prepares a Lua thread and environment, queues script requests, and processes them from its scheduler hook.

01 · InitializePrepare and sandbox the executor Lua thread.
02 · RegisterInitialize libraries, globals, and bootstrap scripts.
03 · QueueSubmit script text through the execution request queue.
04 · RunThe scheduler hook drains pending scripts and yield work.

08 / Complete reference

Function-by-function Luau reference

This section enumerates every function exported by the library registration calls found in the supplied archive. Each entry includes its export location, native implementation name, source-derived parameter checks where detectable, and a Luau usage pattern. These are Vynx-specific executor APIs, not standard Roblox or Luau APIs.

How to read examples: Replace placeholder values with values appropriate to your own test environment. An entry marked “argument details not inferred” means the source did not expose a reliable simple signature through the static checks used for this reference; it is not a claim that the function takes no arguments. Native errors may be raised for invalid arguments or unavailable runtime state.

Compatibility and safety notes

  • Global exports are called directly; table exports are called through their namespace.
  • Several names are aliases to the same native function. Alias entries are shown separately so they can be searched and copied.
  • Filesystem functions operate within Vynx's configured workspace and include path restrictions in the implementation.
  • Input functions can affect the desktop outside the game. Test only with applications and accounts you control.
  • Some introspection, hook, network, and runtime functions are implementation-specific and may be restricted by the host or game.
